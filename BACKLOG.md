## Safety

- [x] **Add watchdog timer.** Enabled the ATtiny85's internal WDT at 2s (`wdt_enable(WDTO_2S)` in `setup()`, `wdt_reset()` at the top of `loop()`), matching the sibling AquariumATO project's convention. `wdt_disable()` at the very start of `setup()` clears any watchdog state left by a prior reset before rearming. Verified via `pio run -e usbasp`: cost is +66 bytes flash (2306 → 2372, 39.5% of 6012), RAM unchanged.
  - Ref: `src/main/main.cpp`

- [x] ~~Add a maximum valve-open timeout~~ — **rejected**. RO fill times are hours and vary by tank/membrane, and there's no EEPROM/serial console here to tune a constant per-installation (unlike AquariumATO's `PUMP_MAX_ON_MS`). A hardcoded timeout would either nuisance-trip or add negligible protection beyond the existing independent high-level sensor. Not worth the complexity — revisit only if a config mechanism gets added for other reasons.

## Test coverage

- [x] **Make `Buzzer` and `SwitchableWithDelay` host-testable without duplication.** Extracted all four classes (`Buzzer`, `Switchable`, `SwitchableWithDelay`, `WaterLevelSensor`) out of `main.cpp` into `include/*.h`, depending only on free functions (`pinMode`/`digitalWrite`/`digitalRead`/`millis`/`delay`) rather than `<Arduino.h>` directly, so the same headers compile against the real core on-device and against a host test double. Each timing method got a `uint32_t nowMs` overload (pure, deterministic) plus a zero-arg convenience overload (`millis()`-based, used by production code) — pattern borrowed from `AquariumAto`'s `Timer`/`TimedSwitchable`/`LiquidLevelSensor`.
- [x] **Class file layout, discussed and decided 2026-09-02:** one class per file under `include/` (`Buzzer.h`, `Switchable.h`, `SwitchableWithDelay.h`, `WaterLevelSensor.h`), no umbrella header — `main.cpp`/`controllerTest.cpp` each `#include` exactly the classes they use directly, so "where did this class come from" is answerable from the include list alone. `include/` (not `lib/`) because PlatformIO auto-adds it to the build path with no config, and it mirrors `AquariumAto`'s own `include/ato/` "project-specific, not a reusable module" convention — `lib/` is reserved there for things meant to be independently reusable, which these four tightly-coupled classes aren't. `CMakeLists.txt` updated with an explicit `include_directories(include)` to match (PlatformIO needs no such change).
- [x] Replaced `test/buzzerTest.cpp` + `test/MockCommon.h` (which reimplemented `Buzzer` from scratch) with `test/ArduinoTestDouble.h` (minimal host stand-in for the Arduino functions these headers need, with a fake pin-state array and controllable fake clock) and `test/controllerTest.cpp`, which includes and drives the real production classes directly. `test/CMakeLists.txt` updated to build `ControllerTest`. Verified: builds and `ctest` passes.
- [x] Added regression tests in `test/controllerTest.cpp` for the class-level behaviors originally listed in the instructions file (now `CLAUDE.md`, then `claude_custom_instructions.md` §11 — see the doc rework below) — buzzer start/repeat/stop, `millis()` rollover, 16-second-style anti-chatter delay in both directions, immediate-shutdown bypass, sensor polarity — including a test that pins down the `lastStateChangeMs == 0ul` sentinel corner case discovered while writing these (see Minor cleanup below) as accepted/documented behavior rather than a silent gap.
  - **Deliberately not covered:** "high-level sensor always forces valve OFF" / "overrides normal sensor" — these are properties of `loop()`'s composition of the (now well-tested) classes, not of the classes themselves. `loop()` reads real hardware pins directly and isn't easily driven from a host test without either extracting a pure decision function or adding hardware mocking beyond what these headers need — judged not worth it for ~10 lines of directly-readable if/else. Revisit if `loop()`'s logic ever grows past trivial.

## Minor cleanup

- [x] Remove unused `WaterLevelSensor::isSensingWater()` — only `isNotSensingWater()` is called in `loop()`. Done as part of the class-header extraction.
- [x] Add a short comment on `SwitchableWithDelay`'s `lastStateChangeMs == 0ul` sentinel explaining it means "never changed," not "changed at time 0." Done as part of the class-header extraction — and writing the regression tests actually hit this corner case live (a state change landing at fake `millis()==0` bypasses the delay on the next call), now pinned down by `test_switchable_with_delay_zero_millis_sentinel_corner_case` rather than left as a surprise.
  - Ref: `include/*.h`
- [x] Fix `CMakeLists.txt` — resolved the AVR toolchain and Arduino core via PlatformIO's own packages (`~/.platformio` / `%USERPROFILE%\.platformio`, cross-platform, already a project dependency) instead of a hardcoded Windows `ARDUINO_DIR`, and dropped the reference to nonexistent `include/Buzzer.h`. Verified end-to-end on Ubuntu: `cmake -S . -B build && cmake --build build` now actually produces a linked `RodiController` ELF (112 bytes RAM / 2350 bytes flash, matching `pio run -e usbasp`'s 112/2306 almost exactly). Along the way, fixed real bugs that made the previous file non-functional beyond the Windows path (all pre-existing, not introduced by this pass):
  - `CMAKE_SYSTEM_NAME`/`CMAKE_C_COMPILER` were set *after* `project()`, which CMake silently ignores — the AVR build was actually compiling with the host's plain `gcc`, not `avr-gcc`.
  - `-mmcu=attiny85` was C-only, never applied to `.cpp` files, so ATtiny85-specific code paths in the framework never got enabled for C++ sources.
  - The core sources were compiled straight into the executable instead of a static library, so dead-code elimination didn't happen and the link overflowed flash by ~9KB. Now built as a `FrameworkArduino` static lib + `-ffunction-sections`/`--gc-sections`, matching PlatformIO's actual recipe.
  - `test/CMakeLists.txt` can no longer be `add_subdirectory()`'d from the top level (the AVR compiler choice is fixed for the whole configure) — split into its own standalone `project(ControllerTest CXX)`, built independently via `cmake -S test -B test/cmake-build-debug`. Verified: builds and `ctest` passes with the host's default `g++`.
  - [ ] Verify the Windows side too (`%USERPROFILE%\.platformio` path, MinGW/MSVC generator) — only Ubuntu has been confirmed so far.
- [x] **8 MHz vs 16.5 MHz discrepancy, resolved 2026-09-03 as part of the documentation rework below.** `README.md`'s new Build section now states the real, verified value (16.5 MHz, per the board's PlatformIO definition and what `pio run -e usbasp` actually builds/links against) as the authoritative fact, and the instructions file (`CLAUDE.md`) no longer states a clock value at all — it points to `README.md` instead, so the two can't disagree again the way they just did.

- [x] **Unify CLion/VS Code CMake build-directory naming, 2026-09-02.** CLion defaults to `cmake-build-<type>` (already what this repo's `.gitignore` expects via `cmake-*`/`test/cmake-*`); VS Code's CMake Tools extension defaults to a plain `build` instead, which doesn't match those patterns and shows up as an untracked stray. Fixed with a new `.vscode/settings.json`: `"cmake.buildDirectory": "${sourceDirectory}/cmake-build-${buildType}"` — `${sourceDirectory}` (not `${workspaceFolder}`) matters here specifically because this repo has two independent CMake projects (root + `test/`), so each needs its own build dir rather than colliding into one. Verified the resulting command (`cmake -S test -B test/cmake-build-debug`) builds and `ctest` passes. Also deleted the stray pre-existing `test/build` dir and updated the doc'd manual-build commands in `CMakeLists.txt`/`test/CMakeLists.txt` to the new naming.
- [x] `.gitignore`: added `.idea` (was untracked and unignored, unlike the equivalent line already in `AquariumAto`'s `.gitignore`). Changed bare `.vscode` to `.vscode/*` + `!.vscode/settings.json`, so the hand-written `cmake.buildDirectory` override is tracked/shared while the rest of `.vscode/` (PlatformIO's auto-generated `c_cpp_properties.json`/`extensions.json`/`launch.json`) stays ignored as machine-specific.

- [x] **Buzzer pattern arrays must have even length, discussed and decided 2026-09-03.** `Buzzer::process()` toggles the pin at every interval boundary unconditionally, so with an odd `N` the wrap from the last interval back to index 0 is *also* a toggle — every slot's ON/OFF role flips on alternating repeats, and the true period becomes `2×sum(array)` instead of `sum(array)`. Added `static_assert(N % 2 == 0, ...)` in `include/Buzzer.h` with a class-comment explanation (confirmed by hand-tracing a 5-element example, and separately confirmed the assert actually fires by compiling a deliberate odd-`N` case standalone). `main.cpp`'s `BUZZ_INTERVALS` is now derived from `buzzIntervalDurations`'s own size (`sizeof(...)/sizeof(...[0])`) rather than hand-counted, so the two can never drift apart — a naive `sizeof`-comparing `static_assert` was considered and rejected first, since the array's declared bound and the hand-counted constant were the same value by construction and such a check would be vacuous.
  - Note: this also *found* a bug in the tests themselves — both existing `controllerTest.cpp` buzzer tests used odd `N` (`Buzzer<3>`, `Buzzer<1>`), and one of them was asserting the flipped-slot behavior as if it were correct. Both rewritten with even-length interval arrays; the rollover test now also explicitly checks the wrap-back-to-index-0 phase.
- [x] Extracted the fake pin numbers reused across `test/controllerTest.cpp` (`5`/`6`/`7`, inlined at ~30 call sites) into named `TEST_BUZZER_PIN`/`TEST_VALVE_PIN`/`TEST_SENSOR_PIN` constants.

## Explicitly out of scope

- **No shared library between this project and `AquariumAto`.** Different MCU (ATtiny85 vs ATmega328), different constraint budget (512B vs 2KB SRAM), and `AquariumAto/lib/` relies on `virtual`/vtable-based `Runnable`/`AbstractSwitchable` patterns this project deliberately avoids. Borrow *patterns* (see `process(nowMs)` above) on a case-by-case basis, not code.
